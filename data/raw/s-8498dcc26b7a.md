When we gathered at GitHub Universe in October 2025 , working with agents in VS Code was still relatively new. A year later, working with agents has become the new normal. A single developer can put several agents to work on different problems, keep coding while those tasks move forward, and check back in to review the results. Work can continue on another machine, in another app, or in the cloud after your laptop closes. The editor that helps you write code is also becoming the place where you coordinate much more of the work it takes to ship software.
A year later, working with agents has become the new normal.
Imagine handing off a feature to Copilot, while an agent using the Claude harness investigates a bug, then opening the running app in a browser that both you and the agent can see and control. Project instructions and tools give those agents the context to work, and the Agents window brings their progress and changes together for review.
When you hand a task to an agent, it shouldn't matter which app you're using to launch the task. When you switch to another tool, the task should continue running. Over the last releases, we've worked to make these connected, continuous experiences across VS Code and other Copilot apps become reality.
In this blog post, we're zooming into how far VS Code has come since the last Universe, and what you can do with it today.
Agents that keep working
Developers can hand off more of the work without handing over the decisions that matter. We built on our Language Server Protocol and Debug Adapter Protocol experience to create the Agent Host Protocol (AHP) , which just went 1.0.
Just as a language server makes code completion and Go to Definition available to different editors, an Agent Host brings agent functionality into an independent process. It manages sessions and provides access to multiple harnesses, models, files, and terminals.
AHP lets clients connect to those sessions and stay in sync. Cloud sessions run on GitHub's infrastructure, so closing your laptop doesn't stop them. You can continue the same session in VS Code, the GitHub Copilot app, GitHub Mobile, github.com, or Copilot CLI. And because the protocol is open, anyone can build a client that works with the same live sessions as VS Code.
Choosing your agent
The agent harness is what coordinates the agent loop and connects the language model to context and tools.
We combined our Local VS Code harness with the Copilot CLI harness to create the new Copilot harness, now the default for new sessions in both the editor and Agents window. Built on the Microsoft Copilot SDK developed by GitHub, it brings more consistent agent behavior across VS Code, Copilot CLI, and the GitHub Copilot app. This also means that you can reuse your agent customizations across different Copilot experiences without modifications.
You can also use the Claude and Codex harnesses in VS Code through the Agent Host. Each runs on its provider’s own agent harness , with its own runtime and capabilities. VS Code brings their sessions together in one place, where you can manage work across agents without requiring every agent to work the same way.
Choosing your model
Access to multiple models remains one of Copilot's pillars. The model picker lets you select from Copilot and bring your own key models. You can specify options like reasoning effort and context size to optimize the model configuration for the task.
As newer and more capable models become available, choosing the right model for the task is becoming more and more difficult. Maybe one model is not the best for each part of the task.
Copilot Fusion autonomously chooses one model or orchestrates a set of models to solve the task at hand. In the Agents Window, you can also use the Compare Models feature in Preview to run different models and harnesses on the same task, review results side by side, and combine the best ideas. Together, these options help you balance speed, cost, and quality.
Managing parallel work
The work we started with Agent HQ in VS Code has grown into the Agents Window , a dedicated space to manage agents across all your workspaces and environments. Run agent sessions in parallel, follow progress, and review changes from a single interface. Seamlessly switch between the editor and the Agents window without starting over. Both views stay in sync with the same live Copilot session. For recurring tasks, use automations , either locally or in the cloud. To avoid conflicts, worktrees help you keep changes isolated between agents.
And when you need to dive into the code or run a debugging session, you can switch to the editor and back to the Agents window at any time. Your active sessions remain running uninterrupted.
The Agent Host is a separate process that lets the Agents window connect to multiple agent sessions at once, including those on remote machines over SSH or dev tunnels, or sessions running in the cloud. Remote agents use that machine's code, tools, and dependencies and keep working after you disconnect, as long as the machine and host stay running.
Shaping your agents
Instructions, skills, hooks, custom agents, and plugins help agents understand your project conventions and workflows. Projects already customized for the Claude Code or OpenAI Codex developer tools can use that setup with their respective harnesses, without rebuilding it for VS Code.
Support for the Model Context Protocol , including MCP Apps, connects agents to your tools and services. Extension authors can contribute agent tools and MCP servers through the Marketplace.
Copilot connectors , now in preview, bring context from services such as Slack, Notion, and Microsoft Learn into your agent sessions without requiring you to install or manage an MCP server. Connect once and reuse the connection across supported Copilot clients signed in with the same account. Connectors work with the Copilot harness and are available on all Copilot plans. For Business and Enterprise plans, administrators must allow editor preview features.
For organizations, managed settings apply policies across teams, while sandboxing can restrict agent access to files and network resources.
Beyond the chat
The integrated browser gives you and your agent a shared view of a page, so you can both see and interact with it without leaving VS Code. Your agent can use Playwright to test a workflow, check the results of its changes, and help identify web accessibility issues.
Some workflows are easier to navigate visually than through a conversation. Canvases , now in preview, let you create interactive interfaces for working with your agent and its context, such as a task board for tracking a project. You can also choose from readily available canvases . The Markdown editor lets you edit a rendered plan or document directly and leave comments for your agent to act on, rather than describing every revision in chat.
Completing a task might mean working with a desktop application that doesn’t have an MCP server or another tool integration. Experimental computer use lets your agent interact with those applications on macOS and Windows by clicking controls and editing text. You control application access, and organizations can disable it through policy.
With models that support image generation, you can create visual assets for your project alongside the code, whether you’re exploring a design idea or building a prototype.
For a little fun, there's Blobby , the VS Code pet who reacts as you work with agents, with achievements to unlock along the way.
Still your editor
We remain just as committed to the editor you rely on every day. Precision editing, code completion, navigation, refactoring, and debugging remain at the heart of VS Code. Next edit suggestions continue to improve with new models and are available to Copilot Free users.
The extension ecosystem remains central to making VS Code your own, from language support to AI extensions like Claude Code and Codex. And it has never been easier to build your own extension .
Last, but not least, our UI modernization work brings shared design choices to the editor and Agents window for a clearer, more consistent experience that preserves your customization and familiar workflows.
Feedback and ideas from the VS Code community have shaped how the product has evolved over the past year. Please keep sharing what is working and what could be better in VS Code GitHub issues !
Happy coding! 💙
